# Tactical 动作池与三拍优先队列 - 产品需求文档

## 需求描述

### 背景

- **业务问题**：Action Run 进入 Tactical Mode 后三拍默认为空，玩家必须逐槽手动造命令；实时战斗又足以处理多数局面，导致主创新在真实对局中缺乏吸引力。
- **目标用户**：首次体验 EchoZero 的参赛评委和普通玩家。
- **价值主张**：按 Q 即刻看到可调整的行动方案，通过改变优先级让前三项形成三拍并立刻看到同源因果预演。

### 功能概述

- 进入 Tactical Mode 时，根据当前朝向、位置和敌人生成不少于 6 条候选动作。
- 候选动作按优先级纵向排列；前三条标记为“执行”，其余标记为“候补”。
- 玩家选择候选动作后可上移或下移，前三条实时映射为三个命令槽。
- Preview 与 Execute 均只使用当前优先级最高的三条命令，并继续调用同一个模拟器。
- 不新增命令类型、角色、敌人、关卡或第二套结算逻辑。

### 用户交互

- `Q`：进入或退出 Tactical Mode。
- `1`～`6` 或鼠标：选中候选动作。
- `W/S`、方向键上下或鼠标按钮：调整选中动作优先级。
- `Enter`：执行前三条；Preview 在每次排序后即时刷新。
- 候选包括护盾、牵引/推击以及不同方向的位移；无目标动作允许保留并在预演中明确显示落空结果。

## 设计决策

- 动作池属于 `ActionRun` 领域状态，UI 只负责选择与排序。
- `commands` 是动作池前三项重新编号为槽位 1～3 后的只读投影。
- 候选动作确定性生成，不消耗 RNG；固定状态必定得到固定动作池。
- 保留现有 `set_tactical_command` 兼容既有测试与局面工具，但正式 Action UI 使用优先队列。

## 验收标准

- [x] 进入 Tactical Mode 时动作池不少于 6 项且前三拍不全为空。
- [x] 调整任一候选优先级后，前三拍顺序与 Preview 同步变化。
- [x] Execute 只执行当前优先级最高的三项。
- [x] Preview 终态等于同一前三拍真实 Execute 终态。
- [x] Stable / Reverse、Protocol 和 Enemy Intent 仍由现有模拟器结算。
- [x] 键盘与鼠标均可完成选择、排序、执行和退出。
- [x] 纯领域测试、Action App 测试及全量回归通过。

## 范围与风险

- 不以堆叠敌人生命或数量作为本轮主要难度调整。
- 不开发自动推荐最优解；动作池只提供可解释的原子动作。
- 若界面空间不足，优先压缩候补行的说明，不隐藏前三拍和 Preview 结果。
